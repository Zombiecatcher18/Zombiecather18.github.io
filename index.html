Featured Project

Project R — Turn-Based RPG with QTE Combat

An original RPG in active development. Players build a combo from a hand of moves, then execute each move through a timed QTE challenge. Enemies learn your patterns and counter predictable behavior — combat rewards timing, sequencing, and unpredictability, not just raw stats.

Systems I Built

  • Turn-based battle loop — alternating turns with a tug-of-war turn meter between player and enemy momentum
  • QTE combo execution — timing bar + button prompt variants, per-hit resolution, damage scaling by QTE rank
  • Pattern awareness AI — tracks move spam, opener repeats, finisher repeats, and QTE timing; switches to prediction mode to counter repeated behavior
  • Personality profiles — per-enemy behavior profiles (Aggressive, Trickster, Balanced, Adaptive, Defensive) that modify move weighting, QTE speed, fakeout frequency, and counter chance
  • Fakeout system — enemy feints that punish reactive players; fakeout frequency scales with demonstrated player skill
  • Enemy combo builder — shared team slot bar with per-enemy move decks and AI-driven combo construction
  • Synergy & sabotage — enemies cooperate or sabotage based on relationship scores; player moves chain through good/bad synergy lists
  • Bounty / rank progression — bounty accumulates toward level-ups that unlock new moves, increase slots, and expand deck size
  • Multi-enemy battles — target selection, per-enemy anchor points, and multi-target support
  • Full battle lifecycle — setup, combat, victory/defeat, and return to overworld

Technical Highlights

  • Zero-allocation coroutine helpers — WaitCache reuses WaitForSeconds instances to reduce GC pressure during battle loops
  • Cached component references — player controller, character controller, and camera are cached at battle start to avoid GetComponent/FindWithTag calls in hot paths
  • Re-entrancy guards — enemyTurnRunning and battleInitialized flags prevent duplicate coroutine execution and premature turn advancement
  • Runtime data cloning — per-battle enemy state is cloned from ScriptableObjects so mutations (HP loss, stat changes, memory) don't corrupt source assets
  • Personality-driven AI biases — all behavior modifiers multiply through a shared EnemyPersonalityProfile, allowing tuning without code changes
  • Pattern tracking with history trimming — AI memory uses fixed-size lists with TrimHistory() to bound growth over long battles
  • Decoupled move data — AttackMove ScriptableObjects allow moves to be authored, balanced, and linked for synergy without touching code
